# nsjail Sandbox for DITA Processing

An nsjail-based process sandbox designed to run DITA-OT transformations in isolation. `sandbox_dita.sh` stacks four isolation layers: `prlimit` (1 GiB virtual-address-space cap, 1024 file descriptors), `taskset` (single-core CPU pinning), and `nsjail` (new mount, network, PID, UTS, and IPC namespaces; chroot to a minimal rootfs; read-only bind mounts exposing only the DITA project tree and required system libraries; writable tmpfs for `/tmp` and `/dev`; all dangerous capabilities dropped). Inside the jail a Python3 HTTP server binds exclusively to `127.0.0.1` so the sandboxed process can fetch DITA content over a loopback-only network without any external connectivity. `nsjail.cfg` is the equivalent protobuf configuration for driving nsjail directly.
