Learn Style and AI Rules

Microsoft Learn steers writers and AI assistants through a style guide, a Copilot instructions file, one repo skill, AI-usage metadata and build rules. This page lists each rule, measures how often the current Markdown breaks it, and says where the rule should live after the DITA port. The main result: once content is semantic XML, 14 of the 21 Copilot rules stop being prompt text and become schema or Schematron checks an agent can run. The other 7 are judgment about voice and clarity.

Anatomy of the skill, and where each part goes

The Extended Zones skill is a good sample of what writers put into AI instructions today. Most of it restates structure that a DITA schema can enforce. Only the domain facts and naming judgment need to stay as text.

Proposed AI layer for the port

Instructions say what to do; tools prove it was done. Every rule that a schema or Schematron can decide moves out of prompt text, and the agent gets the validator as a tool. Step 1 keeps the existing files unchanged, because they still govern the generated Markdown.

Instructions · step 2
AGENTS.md (Learn-wide block)
  • Same two-block layout and sentinel comment as today's Copilot file.
  • A table from Markdown habit to DITA element: bold UI → <uicontrol>, backticks → <filepath> / <codeph>, product names → <keyword keyref>.
  • Only the prose rules (voice, tense, concision, Oxford comma, complete list items).
  • "Run validate before you finish; fix every error."
Skill · step 1
md-to-dita-port
  • Runs the converter on a file set, then the reverse converter.
  • Compares rendered HTML per moniker, pivot and tab.
  • Never edits content to make a diff go away; reports it.
Skills · step 2
refactor-<kind>
  • One skill per refactoring: tiny-include-to-key, duplicate-to-conref, topic-to-task, bold-to-uicontrol.
  • Each states its input query, the change, the count it expects to move, and the rollback.
Skill · authoring
write-learn-task
  • Replaces per-team skills like Extended Zones: picks a topic type and template, fills prolog, adds the topicref.
  • Team facts live in a per-docset context file and in warehouse topics to conref.
Skill · quality
fix-findings
  • Reads Schematron SVRL output, applies the SQF fix when one exists, otherwise proposes an edit.
  • Handles ai-usage when the change exceeds 5% of words.
Tools agents need
validate · schematron · render-diff
  • DTD validation fast enough to run per edit (the dtd-validator-throughput experiment in this repo does ~120k files/s).
  • Per-file Schematron with the shared key and pivot index.
  • Rendered-HTML diff for the round trip.

Sketch of the Learn-wide block in DITA terms

## Learn-wide instructions (managed centrally; do not edit)

### AI usage
- Add <othermeta name="ai-usage" content="ai-assisted|ai-generated"/> to the prolog when
  your change is more than 5% of the topic's words. CI checks this.

### Markup (checked by the schema and Schematron; run `validate`)
- UI labels: <uicontrol>; menu paths: <menucascade>. Never <b> for UI.
- Files and folders: <filepath>; code terms: <codeph>; untranslatable text: translate="no".
- Product names: <keyword keyref="…"/> from the product key map. Never type a product name.
- Links inside Learn: keyref, never a learn.microsoft.com URL.
- Steps: <steps>/<step>/<cmd>, starting with an imperative verb.

### Voice (not checkable; follow the Microsoft Writing Style Guide)
- Active voice, second person, present tense, contractions, short sentences.
- Oxford comma. Complete sentences in list items.

What to trust in these numbers

  1. High precision: sequential list numbering, bare URLs, gerund titles, etc., e.g./i.e., click, you should, AI-usage counts. Spot checks found these are nearly all real.
  2. Medium: we/our (some quoted text and customer stories), consecutive headings (FAQ-style question headings under a section heading are often intended), may (the permission sense is allowed).
  3. Low: title-case headings are inflated by product names ("Microsoft Entra", "Azure Communication Services"); please in sql-docs is mostly quoted error messages (one error catalogue include has 199); master in sql-docs is mostly the master system database. These three are exactly the rules semantic markup fixes, because product names, quoted messages and code terms become distinguishable elements.
  4. The Copilot rule "number all ordered list items as 1." is a source-formatting rule. 11,111 and 22,672 lines break it, and it disappears in DITA because <ol> has no literal numbers.
  5. Acrolinx rules and Learn's server-side checks are not public, so "today" lists only what the repos show.
