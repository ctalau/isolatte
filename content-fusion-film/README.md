# Content Fusion — product film system

A code-driven cinematic marketing film for Content Fusion, built with Remotion,
React and React Three Fiber. Every frame is a pure function of the timeline: no
video editor, no keyframe GUI, no non-deterministic animation.

The current build renders a **73.6-second flagship film** at 3840×2160 / 30fps,
with generated narration, plus four cutdowns and eleven isolated scene
compositions — all from one scene definition.

```
npm install
npm run voice       # generate narration (Kokoro, local, no API key)
npm run dev         # Remotion Studio
npm run manifest    # production manifest + consistency check
npm run render:1080 # web master
npm run render:4k   # delivery master
```

---

## What this is

The film tells one story: **fragmented knowledge becomes structured content,
AI works on top of that structure, humans stay in control, and the result
reaches every audience, language and channel.**

Eleven scenes:

| # | Scene | Mode | What it shows |
|---|-------|------|---------------|
| 01 | Fragmentation | hybrid | Real content fragments drifting at three depth bands |
| 02 | Fusion | hybrid | Fragments converge and become the product window |
| 03 | Intelligent creation | DOM 2.5D | **Hero reference scene** — AI proposes, a human accepts, the document reflows |
| 04 | Structure | DOM 2.5D | The topic separates into its content model, then re-locks |
| 05 | Reuse | DOM 2.5D | One component, many linked instances; a change propagates |
| 06 | Human control | DOM 2.5D | A diff, a review, an approval |
| 07 | Adaptation | DOM 2.5D | The same source, four audiences |
| 08 | Localization | DOM 2.5D | Six languages cascading through depth |
| 09 | Publishing | **true 3D** | The product at the centre of a routed system |
| 10 | Hero system | **true 3D** | Crane and orbit over the whole picture |
| 11 | End frame | DOM | Mark, line, call to action |

`docs/production-manifest.json` is the machine-readable version, regenerated by
`npm run manifest`.

## Architecture

### One camera, two renderers

`src/three/camera.ts` defines a shot as keyframes over a frame range.
`evaluateShot()` turns the current frame into a `CameraState`
(`position`, `target`, `fov`, `roll`, `focusZ`, `aperture`). That single state
drives **both**:

* `<CameraRig>` — a real `THREE.PerspectiveCamera` for the WebGL scenes
* `projectToCss()` — CSS 3D transforms for the 2.5D product scenes

So a DOM scene and a WebGL scene describe their moves in the same vocabulary,
and the film can cut between them without the camera language changing under
the viewer. `projectPoint()` projects world coordinates into design pixels so
SVG overlays stay glued to 3D-positioned elements.

`WORLD_UNIT` (235 design px) is calibrated so the nominal shot — camera at
z = 8, fov 32° — renders world geometry 1:1 in the 1920×1080 design space.
Closer magnifies, further shrinks; shot authoring is therefore predictable.

### The 2.5D UI system

Product scenes are **real DOM**, not screenshots, placed inside a CSS 3D scene
graph:

```
<SpatialUI camera={…}>          ← perspective + inverse-camera transform
  <UIPlane x y z rotation …>    ← one depth layer, gets parallax/defocus/depth cueing
    <ProductWindow>             ← the app as a physical object
      <WindowLayer depth={…}>   ← interior layers separate in Z on camera
```

This is why type stays crisp at 4K (see `out/qa/crop4k.png` after a render) and
why the interface can *animate* — a flat screenshot cannot reflow a document
around an accepted AI suggestion.

Depth follows one language, defined in `theme.depth`, from background
atmosphere at z = −4 to foreground transitions at z ≈ 1.6.

### Where true 3D is used

Only scenes 09 and 10 — the system shots — where real perspective across a wide
depth range is the point. They use **UI-as-texture**: cards are drawn into a 2D
canvas with the same loaded Inter face, then mapped onto planes
(`src/three/textures.ts`), so typography matches the DOM scenes exactly.

Card materials are emissive *and* lit: a purely lit dark UI on a dark stage
disappears, so the same texture feeds `emissiveMap` to hold the authored
luminance while the lit component supplies edge falloff and rim highlight.

### Motion

`src/motion/easing.ts` holds every curve in the film by name —
`cinematicEase`, `softLanding`, `fastReveal`, `editorialEase`, `cameraPush`,
`cameraPull`, `objectMerge`. No anonymous cubic-beziers are scattered through
scene files. Anything "random" (fragment placement, camera breathing, grain)
comes from a seeded hash, so parallel frame rendering is reproducible.

### Narration drives the cut

Scene durations are **derived from measured narration length**, not the other
way round:

```
duration = max(visual minimum, leadIn + measuredVoiceFrames + leadOut)
```

Edit a line in `src/film/narration.json`, run `npm run voice`, and the film
re-times itself. `npm run manifest` fails if the copy and the generated audio
have drifted apart.

### Config-driven

`src/film/contentFusionFilm.ts` is the single source of truth for what the film
*is*. Cutdowns (`src/film/cutdowns.ts`) are a selection and re-timing of that
same list — not a second film — which is why `Cut-cut-30`, `Cut-cut-15` and the
two feature cuts exist without a line of new scene code.

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Remotion Studio |
| `npm run voice` | Generate narration for every scene (`-- fusion reuse` for a subset) |
| `npm run capture` | Playwright product capture (see below) |
| `npm run manifest` | Production manifest + narration/audio consistency check |
| `npm run typecheck` | Strict TypeScript |
| `npm run render:preview` | Fast half-scale H.264 for review |
| `npm run render:1080` | 1920×1080 web master |
| `npm run render:4k` | 3840×2160 |
| `npm run render:master` | ProRes 4444, falling back to high-bitrate H.264 |
| `npm run render:scene -- structure` | One scene |
| `npm run render:scene -- structure --stills 0,60,120` | QA stills from one scene |

Set `REMOTION_BROWSER` to reuse an existing Chromium instead of downloading one.

### Compositions

`ContentFusionDebug` (HUD + safe areas + camera readout) · `Cut-*` ·
`Scene-*` (one per scene) · `StyleFrame` (4K still).

## Product truth vs. marketing abstraction

The film separates the two deliberately, and **nothing here is presented as a
capture of the real product**:

* The Content Fusion UI in scenes 02–08 is a **reconstruction** built from React
  components (`src/components/ui/`), chosen because those scenes animate the
  interface. It is labelled `reconstructed` in `src/assets/manifest.ts`.
* Sample content (`src/assets/productContent.ts`) is written for the film. It is
  structurally representative of technical documentation; it is not a customer's
  document.
* The mark, the brand palette and the call to action are marked `placeholder`.
* The abstract scenes (01, 09, 10) are explicitly metaphorical.
* `npm run capture` refuses to run without a real base URL and never fabricates
  a screenshot.

`src/assets/manifest.ts` lists every asset with a status and, for placeholders,
exactly what a real replacement must be.
