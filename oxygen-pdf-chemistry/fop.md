# Reproducing the "Format PDF" Step with Apache FOP

The DITA-OT 4.3.1 PDF build has two expensive stages (§ 2 of `report.md`):

| Stage | Duration | What happens |
|-------|----------|--------------|
| **Build FO** | 24.6 s | DITA-OT transforms 2,757 topics into a single XSL-FO document (`topic.fo`) |
| **Format PDF** | 28.9 s | Apache FOP renders `topic.fo` into paginated PDF (3,104 pages) |

This document explains how to reproduce only the **Format PDF** step, starting
from the pre-generated `topic.fo` file committed alongside this document.

---

## Files in this directory

| File | Description |
|------|-------------|
| `topic.fo` | XSL-FO intermediate file (31 MB, ~2.9 MB in git) produced by `dita --format=pdf` with `-Dclean.temp=no` |
| `fop.sh` | Runs Apache FOP on `topic.fo` and reports wall time + peak RSS |
| `dita-ot-fo-only.sh` | Regenerates `topic.fo` from the DITA sources (needed if sources change) |

---

## Reproducing the PDF render

### Prerequisites

```bash
# DITA-OT 4.3.1 must be present (downloads automatically via run_analysis.py)
WORKDIR=/tmp/oxygen-chemistry-pdf
ls $WORKDIR/dita-ot-4.3.1/bin/dita
```

### Run FOP on the committed `topic.fo`

```bash
cd /path/to/isolatte/oxygen-pdf-chemistry

# Defaults: reads ./topic.fo, writes to /tmp/oxygen-chemistry-pdf/output-fop-standalone/
bash fop.sh

# Override paths
FO_FILE=./topic.fo \
DITA_OT=/tmp/oxygen-chemistry-pdf/dita-ot-4.3.1 \
OUT_PDF=/tmp/my-output/UserManual.pdf \
bash fop.sh
```

Expected output:

```
[fop] FO file    : ./topic.fo (31M)
[fop] Output PDF : /tmp/oxygen-chemistry-pdf/output-fop-standalone/UserManual.pdf
[fop] FOP config : .../org.dita.pdf2.fop/cfg/fop.xconf
... (FOP page rendering log) ...
[fop] Elapsed : 28.9s
[fop] Output PDF : /.../UserManual.pdf (26M, 3104 pages)
```

### Under the hood — what `fop.sh` does

`fop.sh` assembles the classpath from DITA-OT's bundled FOP libraries and
invokes FOP's command-line main class directly:

```
java -Xmx2g \
     -cp fop-core-2.10.jar:fop-events-2.10.jar:fop-util-2.10.jar: \
         fop-pdf-images-2.10.jar:xmlgraphics-commons-2.10.jar:   \
         batik-all-1.18.jar:fontbox-2.0.33.jar:pdfbox-2.0.33.jar:\
         slf4j-api-2.0.7.jar:jcl-over-slf4j-2.0.7.jar:           \
         xml-apis-ext-1.3.04.jar:xml-apis-1.4.01.jar:            \
         logback-classic-1.5.17.jar:logback-core-1.5.17.jar      \
     -Djava.awt.headless=true                                      \
     org.apache.fop.cli.Main                                       \
     -fo   topic.fo                                                \
     -pdf  UserManual.pdf                                          \
     -c    plugins/org.dita.pdf2.fop/cfg/fop.xconf
```

The FOP configuration (`fop.xconf`) lives at
`dita-ot-4.3.1/plugins/org.dita.pdf2.fop/cfg/fop.xconf`
and controls font directories, source/target DPI, and PDF compression.

## Regenerating `topic.fo` from DITA sources

`topic.fo` is generated by DITA-OT's preprocessing + XSLT pipeline.  To
regenerate it (e.g., after updating the userguide sources):

```bash
cd /path/to/isolatte/oxygen-pdf-chemistry

# Requires the userguide checkout and DITA-OT already present
WORKDIR=/tmp/oxygen-chemistry-pdf bash dita-ot-fo-only.sh
```

This runs the full DITA-OT pipeline up to and including `Build FO`, keeps the
temp directory with `-Dclean.temp=no`, copies `topic.fo` here, and leaves the
PDF in `/tmp/oxygen-chemistry-pdf/output-fo-stage/`.

Expected timing: **~44 s** (preprocessing) + **~25 s** (Build FO) = **~69 s**
before the FOP rendering stage begins; total with FOP ≈ 98 s.

## Performance reference

From `report.md` (single run, host: Ubuntu 24.04 · x86_64 · OpenJDK 21):

| Metric | Value |
|--------|-------|
| Wall time (FOP only) | **28.9 s** |
| Peak RSS | **3.15 GB** |
| Average RSS | 2.23 GB |
| Pages rendered | 3,104 |
| Output size | 25.9 MB |
| Input FO size | 31 MB |
| Throughput | ~107 pages / s |

RAM profile: FOP loads pages into memory as it lays them out and does not
stream to disk.  RSS grows from ~1 GB at the start of the rendering phase to
a peak of 3.15 GB near the end, limited by the `-Xmx2g` heap in `fop.sh`
(the DITA-OT build uses the default `-Xmx512m`, which is enough because FOP
invokes GC more aggressively under tighter heap constraints).
